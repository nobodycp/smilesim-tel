# إعادة هيكلة Pearl — المرحلة ١: الشل + الصفحة الرئيسية

هذا السبك يغطي **أول شريحة فقط** من إعادة هيكلة عميقة لكامل الواجهة. السبب والخارطة الكاملة موثقان هون لأن القرارات (الهوية، الخطوط، نطاق الشل) تُتّخذ مرة وحدة وتُستعمل بكل المراحل اللاحقة، لكن التنفيذ شريحة-شريحة: سبك وخطة وتحقق مستقلين لكل مرحلة، متل ما تنص `work-plan.mdc`.

## لماذا

الواجهة الحالية عندها نظام Pearl موثّق بالكامل (`DESIGN.md`, `tokens.css`) منسوخ من `account_manger`، بس التنفيذ الفعلي سطحي: صفحة الهوم فيها كروت KPI شبه فاضية بصرياً (توين ضعيف)، أيقونات رفيعة غير متقنة، حالة فاضية (`EmptyState`) مجرد نص مائل، وصف اختصارات بلا بنية. الدليل: `docs/visual-review/2026-10-30/design-system/after-home-light-ar-1280.jpg`. بالمقابل، `account_manger` (مصدر Pearl) عنده 7,914 سطر CSS مقابل 2,306 سطر بهذا المشروع — الفجوة بعمق التنفيذ مش بتفصيل صغير.

## القرارات المعتمدة (تنطبق على كل المراحل اللاحقة)

1. **الهوية البصرية المرجعية: Pearl الأصلي من `account_manger`** — وليس أسلوب SaaS الحديث (Tailwind) الموجود بمشاريع `saas-foundation` / `hotspot-store` / `e-bill-saas`. أي صفحة جديدة أو مُعاد بناؤها تقتبس من مكونات ونسب `account_manger` (`.rd-card`, `.rd-stat`, `.rd-topbar`...)، مترجمة لتوكنز ومكونات React الحالية.
2. **الطبقة التقنية تبقى كما هي**: Next.js + React + ملفات CSS بتوكنز `--rd-*` المخصصة. لا تحول لـ Tailwind ولا أي إطار CSS جديد. المشكلة تنفيذ وتأليف (composition/craft)، مش اختيار تقني.
3. **الخطوط تبقى Tajawal** (مطابقة لـ `pearl-ui.mdc` والكود الحالي) — **لا** ننتقل لـ IBM Plex Sans Arabic / Noto Kufi Arabic / Inter Tight رغم أنها خطوط `account_manger` الأصلية. التمايز بين العناوين والأرقام والنص العادي يتحقق بالوزن (400/500/700/800) والمسافة، مش بعائلة خط إضافية. يُحدَّث `docs/superpowers/specs/2026-10-30-frontend-audit.md` بإغلاق هذا القرار المعلّق.
4. **الشل (الهيدر + السايدبار + الدرج) داخل نطاق إعادة الهيكلة.** هذا يتجاوز `content-ui.mdc` الحالي ("الهيدر والسايدبار خلصوا، ما تلمسهم"). جزء من مهام هذه المرحلة تحديث `content-ui.mdc` نفسه ليعكس القرار الجديد بدل ما يبقى متناقض مع الكود.
5. **الترتيب العام للمراحل اللاحقة** (كل وحدة سبك/خطة مستقلة لاحقاً): ٢) صفحات الجداول (مستخدمون، أدوار، أرقام، شركات، مزودون، باقات، مهام، عمليات) ٣) صفحات التفاصيل ٤) الفورمز والديالوجز ٥) التقارير والمحاسبة وسجل التدقيق ٦) تسجيل الدخول و2FA.

## نطاق هذه المرحلة

### داخل النطاق

**أيقونات الشل (تأثير عام عبر كل التطبيق):**
- رفع `stroke-width` الافتراضي للـ SVG من `1.8` إلى `2.2` بـ`base.css` (مطابق لوزن أيقونات `account_manger`، `2.2–2.25`). هذا تغيير نطاقه كل أيقونة بالتطبيق — مقبول لأنه تصحيح وزن خط لا كسر تخطيط.
- تنقيح هندسة أيقونات `office-shell.tsx` (home, staff, lock, plans, numbers, providers, sim, tasks, reports, wallet, bell, settings, logout, menu/close, collapse/expand) لتكون متسقة الأسلوب (نفس زوايا الانحناء وسماكة الخط البصرية) بدل أشكال متفاوتة الدقة.

**توب بار (`shell.css`, `chrome.tsx`):**
- توحيد مقاس كل أزرار التحكم الدائرية/المربعة (البحث، المحفظة، الجرس، الثيم، اللغة، الأفتار) على قيمة واحدة موحّدة (مرجع `account_manger`: 2.6rem مربع، نصف قطر 0.85rem، يتحول لمقاس لمسي ≥44px تحت 992px — يُترجم لنظام القياس الحالي بالمشروع بدل نسخ الأرقام حرفياً).
- حالات hover/focus-visible متسقة ومتقنة على كل عناصر التحكم هاي.
- عدم تكرار شريط علوي إضافي؛ البنية الحالية (ترحيب + تاريخ، أدوات، أفتار) تبقى، فقط تُنفَّذ بدقة.

**السايدبار (`office-shell.tsx`, `shell.css`):**
- تنقيح الفراغات والفواصل بين مجموعات التنقل، حالة `active`/`hover` للرابط، والتمايز البصري بين كتلة الماركة (`brand-mark`) والقائمة تحتها.
- نفس بنية التجميع الحالية (المكتب/التشغيل/التقارير) تبقى — لا تغيير بنيوي بالتنقل نفسه.

**مكوّن `.stat` جديد (بديل `.stat-card` الحالي) — يدخل `DESIGN.md` كمكوّن رسمي:**
- تايل أيقونة بحجم واضح، لون التينت حسب الدلالة (success/warning/danger/muted) بتباين كافٍ (مش شفاف جداً متل الحالي).
- رقم كبير tabular بارز، تسمية فوقه، وصف صف meta اختياري تحت (حد فاصل خفيف).
- يُستخدم فوراً بصفحة الهوم، ويصير المرجع لأي صفحة لاحقة تحتاج KPI (بدون إعادة اختراعه لكل صفحة).

**حالة فاضية حقيقية (`EmptyState` بـ`components/empty-state.tsx`):**
- أيقونة بدائرة صغيرة خفيفة + عنوان مكتوم + نص ثانوي اختياري، بدل نص مائل منفرد بوسط الصندوق. تُستخدم أينما ظهرت `EmptyState` حالياً (مش بس الهوم) لأنها مكوّن مشترك واحد.

**صف الاختصارات (الهوم):**
- يتحول من أزرار outline عشوائية اللف إلى شرائح (chip) فيها أيقونة + نص، بانضباط مسافات.

**تركيب صفحة الهوم (`app/page.tsx`):**
- إعادة بناء التركيب الكامل فوق المكونات أعلاه: صف إحصاءات حقيقي، صف اختصارات، ولوحتا "آخر العمليات" و"لوحة الإعلانات" بحالات فاضية وحشو متقنين.

### خارج النطاق (لهذه المرحلة تحديداً)

- أي صفحة غير الهوم والشل (تُعالَج بمراحل لاحقة لها سبك وخطة مستقلان).
- أي تغيير بمنطق الباك إند أو العقود (`lib/api.ts`).
- تغيير الطبقة التقنية (Tailwind، مكتبة أيقونات جاهزة، إلخ) — مرفوض بالكامل حسب القرار ٢.
- تغيير الخطوط — مرفوض حسب القرار ٣.
- أي محتوى تجريبي/بيانات وهمية؛ العمل بصري/تركيبي بحت على المكونات الموجودة.

## التحقق

- لقطات 1280px وmobile (390px) — فاتح وغامق × عربي/إنجليزي/عبري — لصفحة الهوم والشل، بنفس أسلوب `docs/visual-review/`، تُقارن يدوياً مع لقطات `account_manger` المكافئة (حتى لو من نظام مختلف تقنياً) للتأكد من مطابقة مستوى الحرفية (كثافة، تباين، محاذاة).
- `tsc --noEmit` و`next build` يمران بدون أخطاء.
- اختبارات Playwright الموجودة (`tests/desk-head.spec.ts`, `tests/desk-system.spec.ts`, وأي اختبار يلمس أسماء classes بالشل أو الهوم) تُحدَّث إذا تغيرت الأسماء، وتبقى خضراء.
- تحديث `DESIGN.md` (قسم Inner pages / Components) ليوثّق `.stat` والـ EmptyState الجديد كمكوّنات رسمية، وتحديث `content-ui.mdc` لإزالة تجميد الشل، وإغلاق القرار المعلّق بالخطوط بـ`2026-10-30-frontend-audit.md`.
