## Stack

Next.js 16 (App Router) · React 19 · Tailwind CSS v4 (`app/tailwind.css`, ADR 0022) next to the legacy sheets on `--rd-*` tokens (`app/styles/*.css`, in the `legacy` cascade layer until the migration deletes them) · `radix-ui` primitives, used only inside `components/ui/*`, with variants in `class-variance-authority` and classes joined by `lib/cn.ts` `cn()` · TanStack Query · lucide-react · Playwright (e2e on a mock API, `tests/mock-api.mjs`).

## Request path

1. `proxy.ts` — `doorFromHost` (`lib/doors.ts`) → sets `x-door` header + CSP nonce.
2. `app/layout.tsx` — resolves the door again; bare host → `<Doors>` picker; else `DoorProvider` → `DeskSession` → `AppFrame` (shell).
3. Pages — 26 of 27 are `'use client'` and fetch after mount. Layer guard is client-side `useRequireLayer` (redirect after mount).
4. `lib/http.ts` `request()` (called by `features/*/api.ts`) reads the door from `window.location`, sends cookie `sid` + `x-door`; 401/door mismatch → `window.location.assign('/login')` (hard reload).

## State and data

- **Server state:** TanStack Query (`lib/query.tsx`: `QueryProvider`, `queryKeys`, `unwrap()`, `ApiFailure`), ADR 0001. Wraps the office doors in `app/layout.tsx`.
- **Session:** `DeskSession` runs `queryKeys.me` (read once, `staleTime: Infinity`; own 2–30 s backoff while the API is away, 4xx final) and `queryKeys.directory`. Same context as before (`ready`, `failed`, `retrying`, `retry`, `refresh`, `me`, `names`); once `me` answered the page stays drawn. Name/balance cookies seed the shell for SSR. `refresh()` invalidates `me`; `useAction` calls it after every successful write.
- **Fetching:** every list of the API answers `Page<Row>` = `{ items, nextCursor, total }` plus its own extra keys (`lib/api-types.ts`); `pageRows()` (`lib/use-paged.ts`) hands one answer to the pager, and `allPages()` (`lib/all-pages.ts`) reads a short list whole, page after page (the directory in `lib/directory.ts`: `directoryNames()` for the session's name map, `everyAccount()` for the account pickers and the shell search; the balances report). `usePaged` (cursor lists: numbers, tasks, users, audit, finance, wallet, provider operations, notices, reports) runs on `useInfiniteQuery`, key `['paged', pathname, key]`: keep-previous rows (`stale`), `reload()` invalidates every filter of that list, always revalidated, errors translated when drawn. `useApiQuery(key, fetcher, { enabled, fresh })` (`lib/use-api-query.ts`) is every single read: `data`, a translated `error`, `loaded`, `reload`, over a cached query. `sharedKeys` in `lib/query.tsx` (`packages`, `users`, `companies`, `providers`, `roles`, `home`, `line(id)`, …) are shared between screens (the roles list and the users page's staff-role dropdown read one `roles` entry; the packages and companies screens one `companies` entry). `packageKeys(code)` group a package sheet's own reads, the line-prices table included (an action invalidates `packageKeys.all`). `fresh: true` drops the answer when its screen closes, for editors that copy it into drafts once: the branding draft and the line-prices table always open on a new read. `useLoad` is gone (4.5c). `useAction` (mutation + `onDone` reload + `me` refresh). Each page owns its error/note `useState`.
- **Prefs:** locale, theme, page size via `useSyncExternalStore` over `document.cookie`. Theme defaults to dark (`parseTheme`, `readTheme`) unless «light» is saved.
- **i18n:** API errors are translated by **code** first, then by the Arabic message (`apiText(result)`; `Fetched` carries `code`). Still open: a hook stores the translated text, so an error on screen keeps its language after a locale switch (goes away as lists move to queries).
- **URL state:** `lib/url-state.ts` — `useUrlFilters(keys)` keeps a list's filters in the query string (`router.replace`, scroll kept, each write builds on the last pending one); `useDebouncedField` keeps typing local and commits after 300 ms. Used by numbers, tasks, users.

## Design system

Tokens in `app/styles/tokens.css` (Graphite since 2026-11-09, dark default; their Tailwind names in `app/tailwind.css` `@theme inline` since migration T1.1): `--rd-*` colours/shadows for both themes, `--rd-cut` and `--rd-glow`, `--rd-primary-soft`, `--rd-line-strong` (ink at 11%, one `:root` definition that follows the theme; UI maintenance P1.2), `--rd-accent-fill` / `--rd-accent-fill-hover` / `--rd-on-accent` (a crimson fill that carries content and what is drawn on it; `--rd-accent` stays the thread, ADR 0021 D1), `--rd-login-*`, and theme-independent scales `--rd-radius-{xs,sm,md,card,panel,pill,lg}` and `--rd-text-{2xs…2xl}`. The old alias set is gone (5.3a). Spacing `--rd-space-*`, layers `--rd-z-*` and motion `--rd-dur-*` / `--rd-ease-*` since 5.3d. Rules: `DESIGN.md`, `.cursor/rules/smilesim-ui.mdc`, `direction-theme.mdc`, `content-ui.mdc`, `screen-size.mdc`.

`scripts/contrast.mjs` (no dependency; `node scripts/contrast.mjs` from `apps/web`) resolves `tokens.css` in both themes and scans every sheet `app/globals.css` imports, in cascade order, for a crimson fill (the colour component of a `background` / `background-color` value — so `var(--rd-accent) no-repeat` counts, while a crimson glow inside a gradient does not — being `var(--rd-accent)`, `var(--rd-accent-fill[-hover])` or a `color-mix(…--rd-accent…)` recipe; and any state rule — `:hover`, `:active`, `:focus…`, `:checked` — of such a selector that sets a background or only a new `color`, and any variant of it — an attribute selector, a class or a pseudo-class added, or an ancestor in front — that sets only a new `color`). For each it prints the ratio, per theme, of what is drawn on the fill — `color` (a translucent one composited over the fill), an `svg` `stroke`, a `::before` mark; when the selector and its states set none, the content is read from the selectors it extends, so a variant such as `.ui-btn.ui-btn-primary[aria-pressed='true']` with a new fill is measured under the text it inherits — and, for a fill whose content is drawn by other elements over it (its `OVERLAY` table: the sign-in art's heading and line over `.gauth-art-tag`, composited at the tag's opacity on the art's backdrops), those colours too; it exits 1 when text is under 4.5:1, a glyph-only mark under 3:1, an `OVERLAY` selector is no longer a fill, a bare `var(--rd-accent)` fill is not on its allowlist (decoration and dead rules, each with its reason), or a crimson fill off the allowlist has no content that can be found. `--self-test` runs eighteen cases (an unlisted bare fill, a shorthand or layered bare fill, a bare fill inside `@media`, a hover back to the bare accent, a hover that only changes the text colour, translucent text, the art line at 72% over the tag, the art tag on the bare accent, a lighter fill on a variant written with an attribute selector, an extra class or an ancestor, a variant that only changes the text colour, and a fill with no content off the allowlist must fail; the fill token, a gradient glow, the art in `--rd-login-ink` and a pressed variant on the hover fill must pass). It runs by hand in CHK-LOCAL from UI maintenance P0.9 until P6.4 puts it inside `npm run lint`.

`scripts/check-css.mjs` (postcss; inside `npm run lint` since UI maintenance P1.1) is the CSS guard: twelve counts over `app/styles/**/*.css` — duplicates by (at-rule chain, selector, property), undefined tokens, fallbacks on defined tokens, raw colours, removed outlines, `.5px` / `rem` font sizes, weight 800/900, off-scale `@media` widths, physical properties, literal line-heights, literal spacing and radii, literal disabled opacity — each held at or below its count in `scripts/css-baseline.json` (a ratchet: new hits are printed, a drop prints `ratchet: lower <key> to N`; `--write-baseline` rewrites it, `--list <key>` prints the hits, `--dir` / `--baseline` run it on a scratch copy; a parse error, a nested rule or a nested at-rule fails it loudly; (k) counts a `var()` of any custom property other than a `--rd-` token, which could carry a literal). What each count reads is in its header and in `DESIGN.md` → "Stylesheets" → "CSS guard".

`scripts/check-styles.mjs` (TypeScript parser, no new dependency; `npm run check:styles` from the root or `apps/web` runs `--self-test` and then the tree; CI runs it after check:copy; Tailwind migration T1.2) is the style check for the markup: it reads every string and template literal of the `.ts` / `.tsx` files under `app/`, `components/`, `features/` and `lib/` (comments are not read) and fails, with file:line, on (a) a physical-direction utility as a class token — `ml-` `mr-` `pl-` `pr-` (and `scroll-` forms), `left-` `right-`, `text-left` / `text-right`, `border-l` / `border-r`, `rounded-l` / `rounded-r` and the `rounded-tl/tr/bl/br` corners, `float-` / `clear-` left/right — through variants, `!` and negatives; an inset, margin or padding token counts only with a Tailwind value (number, fraction, `px`, `auto`, `full`, `[…]`, `(…)`), so a legacy class like `pr-badge` does not; a template part ending in such a prefix (`ml-${n}`) does; it prints the logical form; (b) an arbitrary colour inside a class token's brackets (`#hex`, `rgb(`, `hsl(`, `oklch(` and the other colour functions); (c) a JSX `style={{ … }}` colour property (color, background*, any *Color, fill, stroke, border, outline, boxShadow, textShadow) whose value is a string or template literal without `${}` — a computed value (`markColor(name)`, `` `var(${tone})` ``) passes; (d) a `.css` / `.scss` / `.sass` / `.less` file under `apps/web` (dot folders, `node_modules` and the git-ignored outputs not read) other than `app/tailwind.css` and the frozen `LEGACY_SHEETS` list (`globals.css` and the 23 `app/styles/**` sheets); a listed sheet that is gone prints a note to remove it from the list.
