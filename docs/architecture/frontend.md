## Stack

Next.js 16 (App Router) · React 19 · plain CSS on `--rd-*` tokens (`app/styles/*.css`, no Tailwind) · TanStack Query · lucide-react · Playwright (e2e on a mock API, `tests/mock-api.mjs`).

## Request path

1. `proxy.ts` — `doorFromHost` (`lib/doors.ts`) → sets `x-door` header + CSP nonce.
2. `app/layout.tsx` — resolves the door again; bare host → `<Doors>` picker; else `DoorProvider` → `OfficeSession` → `OfficeFrame` (shell).
3. Pages — 26 of 27 are `'use client'` and fetch after mount. Layer guard is client-side `useRequireLayer` (redirect after mount).
4. `lib/http.ts` `request()` (called by `features/*/api.ts`) reads the door from `window.location`, sends cookie `sid` + `x-door`; 401/door mismatch → `window.location.assign('/login')` (hard reload).

## State and data

- **Server state:** TanStack Query (`lib/query.tsx`: `QueryProvider`, `queryKeys`, `unwrap()`, `ApiFailure`), ADR 0001. Wraps the office doors in `app/layout.tsx`.
- **Session:** `OfficeSession` runs `queryKeys.me` (read once, `staleTime: Infinity`; own 2–30 s backoff while the API is away, 4xx final) and `queryKeys.directory`. Same context as before (`ready`, `failed`, `retrying`, `retry`, `refresh`, `me`, `names`); once `me` answered the page stays drawn. Name/balance cookies seed the shell for SSR. `refresh()` invalidates `me`; `useAction` calls it after every successful write.
- **Fetching:** every list of the API answers `Page<Row>` = `{ items, nextCursor, total }` plus its own extra keys (`lib/api-types.ts`); `pageRows()` (`lib/use-paged.ts`) hands one answer to the pager, and `allPages()` (`lib/all-pages.ts`) reads a short list whole, page after page (the directory in `lib/directory.ts`: `directoryNames()` for the session's name map, `everyAccount()` for the account pickers and the shell search; the balances report). `usePaged` (cursor lists: numbers, tasks, users, audit, finance, wallet, provider operations, notices, reports) runs on `useInfiniteQuery`, key `['paged', pathname, key]`: keep-previous rows (`stale`), `reload()` invalidates every filter of that list, always revalidated, errors translated when drawn. `useApiQuery(key, fetcher, { enabled, fresh })` (`lib/use-api-query.ts`) is every single read: `data`, a translated `error`, `loaded`, `reload`, over a cached query. `sharedKeys` in `lib/query.tsx` (`packages`, `users`, `companies`, `providers`, `roles`, `home`, `line(id)`, …) are shared between screens (the roles list and the users page's staff-role dropdown read one `roles` entry; the packages and companies screens one `companies` entry). `packageKeys(code)` group a package sheet's own reads, the line-prices table included (an action invalidates `packageKeys.all`). `fresh: true` drops the answer when its screen closes, for editors that copy it into drafts once: the branding draft and the line-prices table always open on a new read. `useLoad` is gone (4.5c). `useAction` (mutation + `onDone` reload + `me` refresh). Each page owns its error/note `useState`.
- **Prefs:** locale, theme, page size via `useSyncExternalStore` over `document.cookie`. Theme defaults to dark (`parseTheme`, `readTheme`) unless «light» is saved.
- **i18n:** API errors are translated by **code** first, then by the Arabic message (`apiText(result)`; `Fetched` carries `code`). Still open: a hook stores the translated text, so an error on screen keeps its language after a locale switch (goes away as lists move to queries).
- **URL state:** `lib/url-state.ts` — `useUrlFilters(keys)` keeps a list's filters in the query string (`router.replace`, scroll kept, each write builds on the last pending one); `useDebouncedField` keeps typing local and commits after 300 ms. Used by numbers, tasks, users.

  the form of one decision; `components/proposal-card.tsx` the open proposal with approve and refuse, shared by
  the ticket and the queue; `screens/provider-decisions-screen.tsx` the queue (`app/tasks/decisions/page.tsx`).
- **Data:** the ticket's read (`sharedKeys.task`) carries the phase and the hold; the panel asks
  `api.providerDecisionView` (`sharedKeys.taskDecision`) only when the task says `operation.decisions`; the queue
  and the tasks page's link count read `api.providerDecisions` (`sharedKeys.providerDecisions`). All three are
  `fresh`. After a write: the ticket and its decision view are reloaded and the queue invalidated.
- **What is offered is what the API answered** (`decisions`, `canApprove`, `canRefuse`, `blocked`, `needs`); the
  screens hold no rule of who may decide. The tasks page shows the link to an owner or a holder of `accounting`
  in a session of their own, which only spares the others a refusal: the API gates the read.
- **The eSIM code** typed into the decision form is component state of a dialog that is unmounted on close. It is
  sent in the request body and kept nowhere.
- **Styles:** `.po-*` and `.decision-*` in `app/styles/graphite.css`, tokens only; no new primitive.
- **Specs:** `tests/provider-operation.spec.ts`.
